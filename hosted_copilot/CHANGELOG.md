# Hosted Toolkit Changelog

All notable changes to the Hosted Toolkit will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/). The Hosted Toolkit is deployed directly from this source repository, so its history remains unversioned unless its distribution model changes.

## [Unreleased]

### Added

- Introduced the source-deployed Hosted review experiment with compact path-specific guidance for documentation, Go implementation, and acceptance tests, plus controlled paired-review workflows for comparing Hosted and control results.
- Added a normalized Hosted rule catalog and read-only intake workflow that evaluates upstream contributor guidance, Interactive rules, and Maintainer Proposals with reusable semantic assessments, guidance-capacity reporting, portable drafts, and auditable promotion contracts.
- Added versioned source definitions, parser contracts, deterministic collection-only inventories, complete-corpus assessment and reconciliation, and one disposable Workbench display with canonical source and catalog binding.
- Added the Hosted Rule Workbench as a laptop-and-desktop Hosted-rules IDE with searchable candidate and assessment views, persistent decisions, promotion-plan review, guarded capacity projections, source-backed diffs, exact approved-rules export, and repository-read-only loopback serving.
- Added an icon-first Promotion Plan filter that isolates items needing maintainer attention, reports the outstanding count, and follows existing header active, hover, tooltip, and disabled-state behavior.
- Added responsive Rule Issue type paging that keeps labels and counts intact, hides navigation when all tabs fit, and exposes clear Previous and Next edge states on narrower desktop layouts.
- Added transparent waiting panels with accessible title and body text, a muted-gray character chase and three-character white highlight, a smooth 3.5-second multicolor chase on all four pixel-aligned border edges, and reduced-motion support. Edited-rule relationship checks show elapsed time beside the text and a compact blue Cancel button that stops the evaluator worker without losing saved wording or bypassing validation. Icons and local navigation remain responsive during checks, while Promotion Plan uses a compact magnifying-glass Checking pill that stays within its readiness column and opens the running progress panel. Single and bulk Undo remain available, cancel affected checks before their normal reset, and reject late results without clearing unrelated warnings or interrupting replacement checks. Evaluations remain serialized, and authenticated shutdown stops their owned workers. Success shows normal results; failure shows a compact pink error banner with X-only dismissal. Rechecking remains available, and dismissal preserves the validation failure and saved state, keeping the controls readable down to 768px.
- Expanded the pinned, locally hosted Codicon inventory with folder-state, directory-link, workspace-trust, remote-connection, and reconciliation-conflict symbols for current and future Workbench surfaces.
- Added a shared native-PowerShell help renderer across all four normal maintainer commands with side-effect-free `-Help`, `-h`, and `-Detailed` menus, complete native `-?` and `Get-Help` topics, semantic terminal styling, and parameter-set enforcement that keeps help independent from operational requirements.

### Changed

- Integrated saved rule edits with the existing Rule Issues adjudicator, explicit scope guidance, complete-baseline preservation, and refreshed scores, recommendation, applicability, rationale, and related coverage for the exact evaluated wording. Details, Assessment Results, session reload, and approved-rule scoring share the current result. Maintainer-directed consolidation keeps the edited rule as its target and can recommend corrected wording with retirement of fully covered active rules, preserving complete obligations and protected guidance. Recommendations remain advisory until explicit acceptance validates every affected candidate and saves the complete change atomically; failed, cancelled, stale, or interrupted acceptance cannot partially change decisions or discard concurrent work. Accepted intent survives reload and portable import, which requires fresh validation. While an edit awaits a valid assessment, the original assessment remains visible with clear freshness labels; approval stays blocked. This pre-adoption workflow remains subject to the dependency-audit gate and the remaining [implementation checkpoint](docs/HOSTED_COPILOT_CODE_REVIEW_IMPLEMENTATION.md#saved-edit-checkpoint-and-required-repairs-2026-10-16) limitations.
- Aligned Candidate Details and Assessment Results with one documented design: independently collapsible source and coverage evidence, consistently spaced section borders, assessment guidance above bordered inline Priority Score, Token Cost, and Token Headroom metrics, and adjacent Current and Proposed Hosted Rule wording. Shared information panels use a softer 31%-opacity background fill without fading text, icons, or borders; assessment panels use stable `Assessment:` and `Assessment rationale:` labels, with freshness explained in the body. Rule Actions uses one blue-ID heading, non-dismissible action and resource-type guidance, and controls without an extra outer box. Decision Rationale shares the proposed editor's surface styling while preserving its save, disabled-state, and character-limit behavior. Assessment Results retains its read-only applicability and override audit, with a shared lock-icon information banner directly beneath Maintainer Override in both initial and saved states.
- Separated saved-edit Validation Issues from catalog Rule Issues with compact error and warning counters before Saved, persistent failure navigation, Title Case tooltips, and readable status layout down to 768px. Completed wording concerns show one amber AI-issue warning above the proposal in Details and Assessment Results, without a competing recommendation badge or duplicate rationale warning. Nonsensical or unrelated non-rule wording that the evaluator identifies as requiring correction blocks readiness even when scope is accepted and no relationship issues exist; the maintainer's text and selected action remain unchanged, and older results without a wording decision require revalidation. Current Hosted headings show catalog lifecycle status only; advisory recommendations belong to the proposal, with Defer in amber. Plan actions and status-bar warnings target the actual missing input or validation concern rather than always focusing decision rationale, and unselected candidates expose validation attention without becoming selected. Restored edits needing validation contribute a warning and expose an enabled unchanged-wording check instead of appearing problem-free; older findings are not presented as current results. Catalog Rule Issues tooltips show their breakdown without repeating the visible total. Rule Issues uses a compact collection icon with a filled lower-right exclamation badge instead of duplicating the validation warning triangle.
- Replaced scaled Fluent dialog glyphs with optically correct variants and expanded the pinned offline inventory to 375 complete size-specific Regular/Filled families and 750 icons, including status and workflow semantics plus the approved Arrow, Board, Book, Branch, Bot, Brain, Bug, Chat, Chevron, Cloud, Code, Collections, Column, Comment, Content View, Dashboard, and Link domains. The runtime sprite now contains only current UI consumers, the visual inventory shows every vendored icon, native 16px Fluent link glyphs distinguish mapped and unmapped status-bar entries, and Gauge Regular represents remaining Hosted guidance capacity.
