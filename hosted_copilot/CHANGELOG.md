# Hosted Toolkit Changelog

All notable changes to the Hosted Toolkit will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/). The Hosted Toolkit is deployed directly from this source repository, so its history remains unversioned unless its distribution model changes.

## [Unreleased]

### Added

- Introduced the source-deployed Hosted review experiment with compact path-specific guidance for documentation, Go implementation, and acceptance tests, plus controlled paired-review workflows for comparing Hosted and control results.
- Added a normalized Hosted rule catalog and read-only intake workflow that evaluates upstream contributor guidance, Interactive rules, and Maintainer Proposals with reusable semantic assessments, guidance-capacity reporting, portable drafts, and auditable promotion contracts.
- Added versioned source definitions, parser contracts, deterministic collection-only inventories, complete-corpus assessment and reconciliation, and one disposable Workbench display with canonical source and catalog binding.
- Added the Hosted Rule Workbench as a laptop-and-desktop Hosted-rules IDE with searchable candidate and assessment views, persistent decisions, promotion-plan review, guarded capacity projections, source-backed diffs, exact approved-rules export, and repository-read-only loopback serving.
- Added an icon-first Promotion Plan filter that isolates items needing maintainer attention, reports the outstanding count, and follows existing header active, hover, tooltip, and disabled-state behavior.
- Added responsive Rule Issue type paging that keeps labels and counts intact, hides navigation when all tabs fit, and exposes clear Previous and Next edge states on narrower desktop layouts.
- Expanded the pinned, locally hosted Codicon inventory with folder-state, directory-link, workspace-trust, remote-connection, and reconciliation-conflict symbols for current and future Workbench surfaces.
- Added a shared native-PowerShell help renderer across all four normal maintainer commands with side-effect-free `-Help`, `-h`, and `-Detailed` menus, complete native `-?` and `Get-Help` topics, semantic terminal styling, and parameter-set enforcement that keeps help independent from operational requirements.

### Changed

- Replaced scaled Fluent dialog glyphs with optically correct variants and expanded the pinned offline inventory to 375 complete size-specific Regular/Filled families and 750 icons, including status and workflow semantics plus the approved Arrow, Board, Book, Branch, Bot, Brain, Bug, Chat, Chevron, Cloud, Code, Collections, Column, Comment, Content View, Dashboard, and Link domains. The runtime sprite now contains only current UI consumers, the visual inventory shows every vendored icon, native 16px Fluent link glyphs distinguish mapped and unmapped status-bar entries, and Gauge Regular represents remaining Hosted guidance capacity. Existing Codicon and Octicon consumers remain unchanged, while overlapping Fluent assets are intentionally available for future Workbench use.
- Defined concrete import, interface, registration, and callback signals for classifying legacy, typed, and framework-native AzureRM implementations before applying model-specific review rules.
- Replaced the multi-command paired-review interface and ad hoc AI adjudication with one resumable local `Invoke-HostedReview.ps1` workflow that exits while GitHub reviews are pending, guides maintainer adjudication, validates multi-rule findings, and requires explicit cleanup approval.
- Reworked repository-wide review instructions and the review skill to define explicit review identity, task, evidence, trust boundaries, and actionable inline output while correlating implementation, acceptance-test, and documentation changes across the shared provider contract.
- Made the normalized catalog authoritative for generated path-specific guidance, applicability, provenance, and active-rule rendering, with direct source deployment and exact installed-file tracking.
- Made assessment identity and meaning source-local while reconciliation exclusively owns compact Hosted rule synthesis with complete per-member meaning coverage, contingent metadata for deferred and excluded assessments, collision-free recommendations, and explicit implementation-model scope for implementation additions.
- Replaced lane-local reconciliation and bespoke Rule Issue component execution with complete-corpus hierarchical routing, pair-cover consolidation, rehydrated synthesis, and post-synthesis adjudication shards while preserving the version-4 Workbench display and Rule Issues contracts.
- Projected each synthesized recommendation as one scored Workbench parent candidate with read-only contributing-rule evidence, per-member meaning preservation, and unchanged parent-owned decisions, plans, previews, mutations, and Rule Issue operations.
- Hardened Workbench rebuilds for PowerShell-backed Copilot commands and in-process stage status, admitted indivisible synthesis components within the existing hard evaluator envelope, and added aligned cache-aware workloads with calibrated assessment and reconciliation estimates plus immediate worker completion progress.
- Persisted each validated reconciliation shard immediately for automatic interrupted-run reuse, made exact cache reuse the default rebuild behavior, and added `-Rebuild -Force` to bypass assessment and reconciliation cache reads without weakening atomic artifact publication.
- Standardized Hosted validation and test reporting with the Interactive Toolkit execution-state presentation and adopted a guarded four-characters-per-token capacity estimate with 25% safety headroom.
- Organized Hosted tooling around four root-level everyday commands, including explicit `Install-HostedRules.ps1` and `Test-HostedRules.ps1` entrypoints, grouped specialized catalog commands, dedicated internal, module, test, migration, and legacy directories, and permanent layout enforcement.
- Added CODEOWNER-only current-results Bulk Actions that accept evaluated Add and Update recommendations as complete decisions with deterministic rationale, operation-scoped Undo, and preservation of existing or subsequently reviewed manual decisions.
- Simplified Workbench Rule Actions around trusted generated identities and one saved decision: the Details pane now shows an immutable rule header, promotion actions imply plan membership, plain `No Change` clears the decision, and consolidation decisions can retain editable proposed wording plus explicit related-rule retirements as one atomic Plan item.
- Separated fast Workbench launch from explicit source refresh: ordinary launch validates the live CODEOWNER and writable fork context before serving the last jointly validated display and Rule Issues artifacts, while `-Rebuild` owns direct-content cache reuse, isolated semantic regeneration, and atomic publication.
- Routed every Rule Issue through the existing Promotion Plan with reconciliation-owned compound actions, editable wording and retirement selections, exact Preview and approved-rules mutations, and a fail-closed `Needs action` state when reconciliation cannot produce a safe lifecycle recommendation.
- Centralized current Workbench browser behavior under schema-backed Playwright journeys, added headed viewport and fixed-window 100%-through-200% browser-zoom playback with owned-server cleanup and aggregate failure reporting, covered bulk-to-manual tree ownership and color transitions, and retained Puppeteer temporarily as a second consumer of the same viewport suite.
- Centralized Workbench status-bar entry metadata and state rendering behind one declarative service, moved shared geometry to CSS tokens, and standardized authored tooltips on sentence case while preserving product names and generated values.
- Reworked Promotion Preview into a continuous authenticated GitHub-style file review with independently disclosed Proposed, Payload, and Raw Approved Rules trees, persistent file navigation, sticky split-diff headers, muted file and filled folder icons, CODEOWNERS headers, uniform spacing, independent Viewed and collapse controls, a Review changes approval popover, and one contextual full-file approved-rules diff.
- Made large Promotion Previews responsive by virtualizing off-screen diff bodies while retaining every file header, exact scroll geometry, file navigation, disclosure, Viewed state, line expansion, and width-aware placeholder measurement.
- Replaced accepted-generation publication, promotion transactions, and version 3 runtime validation with the direct v4 display, local draft, and approved-rules pipeline; preserved retired source files under the local-only archive.

- Revealed every positive edited-rule relationship review immediately after asynchronous checking, including multiple related rules, while preserving the Details scroll position; redesigned the destructive Rule Action confirmation as a coherent warning with an amber header, a tokenized XP-style information callout with its own navy-to-cyan title strip and one-pixel shimmer divider, and Fluent warning and undo icons.
- Corrected Workbench cache authority so audit-only assessment timestamps and presentation-only Source Assessment, reconciliation, and adjudication output changes no longer invalidate semantic results, while declared semantic behavior changes invalidate the appropriate caches consistently; rebuild output now distinguishes cached artifact reconstruction from model evaluation with concise stages, elapsed summaries, publication status, and condition-aware final results.
- Restored toolkit isolation by distinguishing the Hosted deployment `.github` tree from root Interactive runtime, sourcing installed files only from `hosted_copilot`, and replacing normal Hosted validation reads of live Interactive manifests and catalogs with Hosted-owned checks and synthetic intake fixtures.
- Removed the unreachable blocked-reconciliation Workbench UI, payload schema, builder bypass, approval gate, and regression path now that duplicate target ownership fails before display publication; retained the conflict icons in the local icon inventory.

- Prevented cold server starts from revealing persisted candidate trees before their external icon symbols paint, so Overrides and Contributor Guidance decorations no longer require folder expansion to appear.
- Scoped Workbench npm auditing to the Hosted lockfile, reported installed packages as current when they match the audited lock, and skipped redundant reinstalls without changing remediation behavior for stale or vulnerable graphs.
